## Overview

I'm studying for CompTIA CySA+ (CS0-004), and instead of using a generic flashcard app I
built my own study platform and host it on my homelab. It's a progressive web app I can open
on my phone or laptop, and it covers the whole loop: drilling questions, reading the study
guide, reviewing flashcards, and sitting timed mock exams that match the real exam's format.

It's built for one user (me), so the design choices are about keeping it simple, private,
and light enough to run on a low-power box next to everything else in the lab.

## What it does

**Drill mode** is the day-to-day part. It uses the SM-2 spaced-repetition algorithm to decide
what to show next, one question at a time, with immediate feedback and a running accuracy for
the session. Questions I get wrong come back sooner.

**Mock exam mode** is built to feel like the real test. Each exam draws 85 questions using the
official domain weights (Security Operations 34%, Vulnerability Management 26%, Incident
Response 24%, Reporting and Communication 16%), reserves six slots for performance-based
questions, and runs on a 150-minute countdown. There's no feedback until you submit, the same
as the real exam. After that you get a scaled score, a per-domain breakdown, and a full
review that replays exactly what you answered.

**Performance-based questions** are handled as their own question types. Ordering and
matching questions have their own grading logic, and drill and the mock exam use the same
grading code, so a PBQ is scored the same way wherever it shows up.

There's also a **study guide reader** with saved reading progress, **flashcards** built from
the end-of-chapter exam essentials, and an **analytics** page with per-domain mastery and a
contribution-style heatmap of study activity.

## Getting the questions right

The first version of this project used generated practice questions. When I tested them with
a simple solver that never read the question at all, it scored 83% just by picking the only
answer that ended with a period. That's around the real exam's pass mark. The question bank
was really testing writing style.

So I rebuilt the pipeline around published study material. A script extracts each question,
its choices, and any shared scenario or exhibit from the source. Many questions share a
scenario that the source file nests inside the previous question, so the extractor detects
those groups, pulls the scenario back out, and attaches it to every question it covers. A
second script re-parses the answer sections on its own and fails the build if any stored
answer key disagrees with the source, or if an exhibit image is missing.

## Hosting and access

The app runs in Docker on my home server. Its port is bound to `127.0.0.1` only, so it isn't
reachable from the LAN or the internet directly. The only way in is through a **Cloudflare
Tunnel**, with a **Cloudflare Access** policy in front that allows my email address and
nothing else.

That's also why the app has no login of its own. Identity is checked at the edge before a
request ever reaches the container, and a second, weaker login inside the app wouldn't add
much.

Progress, notes, and scheduling data live in a single **SQLite** file. For one user on a
low-power host, a separate database container would only cost memory. The study books and
anything derived from them are stored in a private bucket on my self-hosted **Supabase
Storage** and fetched at runtime, so they never end up in the Docker image or the code.

## Stack

Next.js and TypeScript for the app, SQLite (better-sqlite3) for progress and scheduling, a
service worker for offline caching and installability, Docker for deployment, Supabase
Storage for private study materials, and Cloudflare Tunnel plus Access for the front door.
