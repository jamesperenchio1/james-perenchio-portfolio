## Overview

My home lab is where I practice the defensive side of security on infrastructure I own and
control. It runs services I use every day, but the part I spend the most time on is the access
model in front of them. The rule is simple: nothing is exposed to the internet directly, and
nothing is trusted just because it's on the network.

It runs on modest hardware: a low-power **Intel N150**, headless, all Linux. I wanted to show
that a solid zero-trust setup comes down to architecture, and doesn't need a rack of servers.

## Zero trust in practice

Being on my network doesn't get a request anywhere. Every request has to prove who it belongs
to before it reaches a service, and there's no trusted interior where that check gets
skipped. Each of the decisions below follows from that.

## The access path

<Diagram />

**No open ports.** I don't forward any ports on the router. Services are only reachable
through a **Cloudflare Tunnel**, which opens an outbound connection from inside the network.
From the public internet there are no inbound ports to scan or probe.

**Single sign-on in front of everything.** **Authentik** runs as a forward-auth proxy ahead of
every service. A request has to be authenticated by Authentik before it's passed through to
any app. That puts identity in one place: one set of accounts, one set of policies, and one
place to grant or revoke someone's access to the whole lab.

**Access is approved out of band.** Adding a new person isn't done by leaving a door open.
Each user is approved individually through a messaging-app workflow, so I can allow or deny
access when the request comes in.

## What runs behind it

Behind the access layer is a **Proxmox** host running Docker workloads, including:

- **Nextcloud** for files and collaboration
- **Immich** for a private photo library
- **Grafana** for dashboards and monitoring
- plus other Docker workloads

New services sit behind the same tunnel and SSO by default, so adding one never means opening
a new port.

## How it fits with the rest of my practice

I do offensive practice on Hack The Box. The lab is the other half: somewhere to build and
defend real infrastructure, make trade-offs, and deal with what breaks. Running forward-auth,
tunnels, and least-privilege access every day has taught me more than reading about them did.
