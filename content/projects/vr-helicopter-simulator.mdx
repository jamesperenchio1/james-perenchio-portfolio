## My focus: how the client talks to the server

A simulator like this isn't one program — it's a client and a game server that have to stay
in lock-step in real time. If they drift, the whole illusion falls apart. The problem I took
on was the communication layer between them.

We researched the options for that layer and landed on **WebSockets**, and building it well
meant getting a genuine handle on networking fundamentals:

- **Persistent connections** — keeping a live, low-latency channel open between client and
  server rather than paying setup cost on every message.
- **Message framing** — defining how state updates are structured and parsed on both ends so
  nothing is ambiguous or malformed.
- **State synchronization** — keeping client and server views of the world consistent in real
  time, which is the hard part of anything multiplayer or simulated.

## Why it still matters to me

It's a satisfying thread back to the aerospace world I work in now — but the deeper reason I
keep it is that the fundamentals under a game are the same ones under everything else. The
skills that keep a helicopter sim's client and server in sync are the same networking skills
that sit under real infrastructure and security work.
